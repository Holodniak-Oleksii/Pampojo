# 15-pwa-shell — technical plan

Spec: `docs/specs/15-pwa-shell.md`
ADR: `docs/adr/0008-serwist-service-worker.md`

## 1. Summary

Make Pampojo an installable PWA whose pages open offline after one online visit.

- **Manifest and icons:** a web app manifest (`src/app/manifest.ts`), with PNG and maskable icons generated from the brand SVG.
- **Service worker:** Serwist through its Turbopack route (`/serwist/sw.js`). It precaches the build and an `/offline` page, caches visited app pages network-first, never caches API or auth, and updates silently on the next launch.
- **Install UI:** a compact install card on Today (phones), an install row in Profile, and an iPhone guide (sheet on phones, dialog on wide screens).
- **Logout** deletes the pages cache.
- **Storage:** `navigator.storage.persist()` is requested once.

There are no server or database changes.

## 2. Acceptance criteria

- **AC1:** On a production build (`next start`):
  - `GET /manifest.webmanifest` returns:
    - `name` and `short_name` "Pampojo", `start_url` "/today", `scope` "/", `id` "/", `display` "standalone", `orientation` "portrait";
    - `background_color` and `theme_color` "#ECE9E4";
    - icons `/icons/icon-192.png` (192, any), `/icons/icon-512.png` (512, any), `/icons/maskable-192.png` (192, maskable) and `/icons/maskable-512.png` (512, maskable).
  - Each icon URL answers 200 with `image/png` and the declared pixel size.
  - After the first load and a reload, `navigator.serviceWorker.controller` is set (the first install claims the page; the check waits for it).
- **AC2:** On a production build:
  - after visiting `/today` online, going offline and loading `/today` shows the app shell (the Today heading);
  - loading a never-visited app page (`/progress`) offline shows the `/offline` page ("No connection").
  - The browser's own offline page never appears.
- **AC3:** When the server starts serving a different `/serwist/sw.js`:
  - the open page installs it into `registration.waiting`;
  - `registration.active` keeps the old script;
  - the page does not reload, and no prompt or toast appears.
- **AC4:** Install UI:
  - with a captured `beforeinstallprompt`, the Today card (below `lg`) and the Profile row call the event's `prompt()`;
  - with an iOS Safari user agent and no prompt, both open the guide;
  - the card's close button hides it, writing `pampojo:install-card-hidden-until` = now + 7 days, and it shows again after that date;
  - when the app runs standalone, or after `appinstalled`, no card and no row render;
  - with no install path (no prompt, not iOS), nothing renders.
- **AC5:** Logging out deletes the `pampojo-pages` cache. A later user on the same device can never get the previous user's cached page offline.
- **AC6:** `requestPersistentStorage()` calls `navigator.storage.persist()` only when the `localStorage` flag `pampojo:storage-persist-requested` is absent, then sets it. It is called:
  - on app mount when running standalone;
  - after a session starts (`useStartSession`).
  - A second call never asks again.
- **AC7:** The lead checks real devices from a Vercel preview, using the checklist in section 10, with screenshots.

export const PAGES_CACHE = 'pampojo-pages';
export const SW_URL = '/serwist/sw.js';
/** App pages the service worker caches network-first. */
export const APP_PAGE_PREFIXES = ['/today', '/calendar', '/library', '/session', '/progress', '/profile'] as const;

The worker and the client both import `PAGES_CACHE` and `APP_PAGE_PREFIXES`. Keep this file free of browser-only code so the worker bundle can import it.

## 4. API

No API changes.

- `GET /manifest.webmanifest` is generated by Next from `src/app/manifest.ts`.
- `GET /serwist/sw.js` is the Serwist route: static, built at `next build`, with `Service-Worker-Allowed: /`.
- `/offline` is a static page.

The proxy matcher already skips URLs with a dot (`sw.js`, `.webmanifest`, `.png`). `/offline` and `/serwist/*` are not protected prefixes.

## 5. Server

No server modules change. Only the Next config and routes change:

- **`next.config.ts`:** wrap the config with `withSerwist` from `@serwist/turbopack`.
- **`src/app/serwist/[path]/route.ts`:** `createSerwistRoute`, with these options:
  - `swSrc: 'src/app/sw.ts'`, `useNativeEsbuild: true`;
  - `additionalPrecacheEntries: [{ url: '/offline', revision }]`, where `revision` = `process.env.VERCEL_GIT_COMMIT_SHA ?? crypto.randomUUID()`;
  - `globIgnores` for source maps if any.
  - Export `dynamic, dynamicParams, revalidate, generateStaticParams, GET` exactly as the package does. The spike showed this builds under `cacheComponents`.

### Dependencies

### Service worker — `src/app/sw.ts`

- **Header:** `/// <reference lib="esnext" />` and `/// <reference lib="webworker" />`; declare `__SW_MANIFEST` on `WorkerGlobalScope` and `self: ServiceWorkerGlobalScope` as in the Serwist docs.
- **`new Serwist(...)` options:**
  - `precacheEntries: self.__SW_MANIFEST`, `skipWaiting: false`, `clientsClaim: true`, `navigationPreload: true`.
  - `runtimeCaching`, in this order:
    1. **API and auth:** `NetworkOnly` for same-origin `/api/**`.
    2. **App pages:** `NetworkFirst({ cacheName: PAGES_CACHE, networkTimeoutSeconds: 4, plugins: [cacheable] })`.
       - It matches a same-origin `GET` whose pathname equals or starts with an `APP_PAGE_PREFIXES` entry plus `/`, with no `_rsc` search param and no `RSC` request header.
       - `cacheable` is a `cacheWillUpdate` plugin that keeps only `status === 200 && !response.redirected` responses whose `content-type` includes `text/html`.
    3. **Everything else:** `NetworkOnly`.
  - `fallbacks.entries: [{ url: '/offline', matcher: ({ request }) => request.destination === 'document' }]`.
- **Listeners:**
  - `serwist.addEventListeners()`.
  - `self.addEventListener('activate', (event) => event.waitUntil(caches.delete(PAGES_CACHE)))`: cached HTML points at the old build's chunks, so a new version starts with an empty pages cache.
- **Comments:** two short ones, on why `skipWaiting` is false and why the pages cache is cleared on activate.
- **Lint and types:** add `src/app/sw.ts` to the ESLint and tsconfig setup only if it fails as is. The file uses worker globals, so a `/* eslint-env serviceworker */` or a tsconfig `lib` entry may be needed. Record any such change in Implementation notes.

### Install state — `src/features/pwa/install.ts` (store) and `useInstall.ts`

- **The store** is a module-level external store, the same pattern as `useTheme`. It holds:
  - `deferred: BeforeInstallPromptEvent | null`;
  - `installed: boolean`.
- **`attachInstallListeners()`:**
  - `beforeinstallprompt` calls `preventDefault()`, then stores the event and emits;
  - `appinstalled` sets `installed = true`, clears `deferred` and emits.
  - It is idempotent and returns a cleanup.
- **`isStandalone()`:** `matchMedia('(display-mode: standalone)').matches || navigator.standalone === true`.
- **`isIosBrowser()`:** `/iPhone|iPad|iPod/.test(ua) || (navigator.platform === 'MacIntel' && navigator.maxTouchPoints > 1)`.
- **`useInstall()`** returns `{ path: 'prompt' | 'ios' | null, promptInstall(): Promise<void> }`:
  - `path` is null when standalone or installed;
  - otherwise `prompt` when an event is stored, `ios` when `isIosBrowser()`, else null.
  - `promptInstall` calls `deferred.prompt()`, awaits `userChoice`, and on `accepted` sets `installed` and clears the event.
  - On the server and during hydration, `path` is null (`useSyncExternalStore` server snapshot).
- **`useInstallCardSnooze()`** returns `{ hidden: boolean, snooze(): void }` from `localStorage`. Every access is in try/catch (private mode); with storage unavailable, the hide lasts for the visit only.
- Types for `BeforeInstallPromptEvent` live in `src/features/pwa/types.ts`.

## 10. Risks and open questions

- **Spike vs real build:** the spike built under `cacheComponents` with the route exports. If a later Next or Serwist version rejects `dynamic`/`revalidate` in the route, wrap the GET in `'use cache'` or fall back to the hand-written worker (ADR 0008). Stop and tell the lead.
- **First load not controlled:** `clientsClaim: true` makes the first install control the open page. The e2e waits for `controller`.
- **Offline page language:** `/offline` is precached in the language of the cookie at install time. That matches the user's language unless they switch it later, which is acceptable.
- **iOS storage eviction:** `persist()` is a request, not a promise. Spec 17's real-device check covers it.
- **CI production server:** blocking service workers globally keeps other suites unchanged. Only `e2e/15` exercises the worker.
- **Manual device checklist (AC7):**

    - open the preview, see the Today card, tap "Встановити", accept;

## 11. Implementation notes
- **Precache:** Serwist already precaches every file in `public/`, including the brand SVGs. Adding them to `additionalPrecacheEntries` as well made `addToPrecacheList` throw ("conflicting entries"), and the worker failed to evaluate. Only `/offline` is an additional entry now.
- **`brand-assets.ts`:** new in `src/features/pwa/`. The offline page and `AppIconTile` use plain `<img>` of the brand SVGs (with an eslint-disable and its reason), because `next/image` would go through `/_next/image`, which is not cached offline. `AppIconTile` is the real `pampojo-icon.svg`, not a drawn "P" (the plan's preferred option).
- **`useInstallAction.ts`:** a small hook shared by the card and the row (prompt or guide), instead of duplicating the click logic.
- **Copy:** `Go to Today` already existed with uk "На головну", so the offline link uses `t('Go to Today', { context: 'offline' })` → "На «Сьогодні»".
- **Guide step tile:** the step 3 "Додати" tile is `min-w-11` with padding, not a fixed 44px square, because the word did not fit.
- **AC3 e2e:** Playwright cannot route the browser's own update fetch of the worker script, so the test registers the same worker at `/serwist/sw.js?v=next`. A changed script URL is an update of the same registration. It then checks that the update waits in `waiting`, that `active` is unchanged, and that the page did not reload.
- **AC6 test:** `persist.test.tsx` runs in the browser project and spies on the real `navigator.storage.persist`.
- **Not in the plan:**
  - `scripts/generate-icons.ts` writes the PWA icons next to its existing outputs, which stay byte-identical;
  - `docs/tech/OFFLINE.md` and `ARCHITECTURE.md` describe the worker.
- **CI formatting:** `pnpm prettier --write` fixed the 22 spec 11 files flagged by CI `format:check`, at the lead's request.

### Findings

1. [blocker until verified] **`/serwist/sw.js` is not prerendered and is built per request** (`src/app/serwist/[path]/route.ts:8`).
   - **Evidence:** the route's `dynamic = 'force-static'` and `generateStaticParams` do not prerender it under `cacheComponents`. The build lists it as `ƒ /serwist/[path]`, there is no prerendered body in `.next/server/app/serwist`, and `.next/prerender-manifest.json` has no entry.
   - **Why it works locally:** `next start` runs in the repository, where `esbuild`, `src/app/sw.ts` and `.next/static` all exist.
   - **Why Vercel likely fails:** the function's trace (`route.js.nft.json`) contains none of them: `esbuild` is a `webpackIgnore` dynamic import, `swSrc` is read at runtime, and the precache globs `.next/static`, which is served from the CDN, not the function. The likely result is a 500 or an empty precache, so no service worker in production. The ADR 0008 spike missed this because it checked `next start` only.
   - **Next step:** open the PR and check `https://<preview>/serwist/sw.js`: 200, about 100 KB, and containing `/_next/static/chunks/` entries.
   - **If it fails:** switch to Serwist's build-time mode (`@serwist/cli` `serwist build` after `next build`, writing `public/sw.js`, the same worker source). That is a dependency change and an ADR 0008 amendment, so the lead decides.
2. [minor] **Pages are cleared only on an explicit logout** (`src/features/auth/LogOutButton/LogOutButton.tsx:59`). If a session expires and another person signs in on the same device, the previous user's cached pages stay until each URL is visited again online. AC5 covers logout only. Clearing `pampojo-pages` on sign-in too, or when the signed-in user id changes, would close the gap.
3. [minor] **The AC2 e2e comment is wrong** (`e2e/15-pwa-shell.spec.ts:94`). It says "the first load ran before the worker took over" and reloads, but the manual walk shows the first visit is cached without a reload. The test should cover the plain first-visit path the spec describes (no reload).
