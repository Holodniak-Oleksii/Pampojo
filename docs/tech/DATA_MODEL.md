# Data model

Draft. Specs refine it during `/drill`; any change here needs the lead's approval. Drizzle schema files live in `src/server/db/schema/<domain>.ts`.

Conventions:

- Primary keys are UUIDs. Client-created rows get their id on the client.
- `createdAt`, `updatedAt` (timestamptz, UTC) on every mutable table. `deletedAt` for soft deletes on rows that sync.
- Canonical units: `kg`, `cm`, `sec`, `m`.
- Enumerations are Postgres text columns checked against `as const` arrays in `src/shared/constants`.

## Auth (Better Auth)

`user`, `session`, `account`, `verification` — generated by Better Auth's Drizzle adapter. Do not hand-edit; extend through `profile`.

## body_measurement

`id`, `userId`, `type` (`weight`, `chest`, `waist`, `hips`, `biceps_left`, `biceps_right`, `thigh_left`, `thigh_right`, `body_fat_pct`, …), `value numeric` (canonical unit), `measuredOn date`, `createdAt`, `updatedAt`, `deletedAt`.

## share_link

`id`, `workoutId`, `ownerId`, `tokenHash` (store only the hash), `expiresAt null`, `revokedAt null`, `importCount int`, `createdAt`.

## ai_request_log (spec 20)

`id`, `userId`, `feature`, `model`, `promptVersion`, `inputTokens`, `outputTokens`, `costUsd`, `latencyMs`, `status`, `createdAt`.

## sync_mutation (spec 16)

`id` (client mutation id, PK), `userId`, `type`, `appliedAt`. Lets the server ignore a replayed mutation.

## Derived values

- **Estimated 1RM:** Epley `weight × (1 + reps / 30)` for sets with 1–12 reps.
- **Volume:** `Σ weight × reps` per exercise, session, week.
- **BMI:** `weightKg / (heightCm / 100)²`, WHO adult categories.
- **Adherence:** completed occurrences ÷ due occurrences for the period (rules in spec 12).
