# Specs

One file per feature, numbered in delivery order (see `docs/product/ROADMAP.md`). A spec says what and why; `scratch/<same-name>.md` says how.

Lifecycle: `/drill` → `/scratch` → `/implement` → `/review`. Specs carry no status line; git history shows progress.

New specs: copy `_TEMPLATE.md`, take the next free number, add the line to the roadmap.
