This guide is the single source of truth for frontend conventions in Pampojo. Skills and `CLAUDE.md` point here instead of restating it.

Configuration wins over prose. `package.json`, `tsconfig.json`, `eslint.config.*` and `components.json` (shadcn) decide versions, scripts and rules. When this guide and a config disagree, follow the config and flag the drift.

## Imports and assets

Import through the `@/` alias, which maps to `src/`. Do not write deep relative chains such as `../../../components/Button`; they break on every move and hide real dependencies. Relative imports are fine inside one feature or component folder.

```ts
// Good
import { Button } from '@/components/ui/button';
import { useWorkouts } from '@/features/workouts/hooks/useWorkouts';

// Bad
import { Button } from '../../../../components/ui/button';
```

Static assets: images that are part of the bundle are imported (`import logo from '@/assets/...'`) or rendered with `next/image`, so the build emits hashed URLs and browsers never keep a stale file. Files in `public/` are only for things that need a fixed URL: PWA icons, the manifest, favicons, brand files used by the service worker.

## Internationalization

UI text goes through `t()` from `react-i18next` from the first screen, even while English is the only locale. Adding a locale later is then a translation job, not a refactor.

The key is the English source string: `t('Start workout')`, not `t('today.startButton')`. Always pass a literal to `t()`; never a variable or a template literal. Extraction (`i18next-parser`) reads source code statically, so a computed key is invisible to it and silently stays untranslated.

When the label depends on runtime data, build a map whose values are already translated, inside a hook next to its consumer:

```ts
export const useMuscleGroupLabel = () => {
  const { t } = useTranslation();
  return useMemo(
    () => ({
      [MUSCLE_GROUP.CHEST]: t('Chest'),
      [MUSCLE_GROUP.BACK]: t('Back'),
    }),
    [t],
  );
};

// Good
labels[muscle];
// Bad — the extractor sees t(<variable>)
t(MUSCLE_KEYS[muscle]);
```

Interpolation uses options, not string building: `t('{{count}} changes pending', { count })`.

## Styling

- Tailwind utility classes with the design tokens from `docs/tech/DESIGN_SYSTEM.md`. No hard-coded hex colors in components.
- Merge classes with `cn()` from `@/lib/utils`.
- shadcn components live in `src/components/ui` and are generated by the shadcn CLI. Change their look through tokens and variants, not by forking markup into features.
- Mobile first: base classes target the phone; `md:`/`lg:` add the desktop layout.

Run `pnpm lint`, `pnpm typecheck` and the test files you touched. Leave the full suite to CI.
